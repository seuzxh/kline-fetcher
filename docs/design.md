# kline-fetcher 技术方案

> 适用版本：v3.0.x。本文档记录实现层面的关键设计决策及其依据。
> 整体架构见 [architecture.md](architecture.md)，接口明细见 [api-reference.md](api-reference.md)。

## 1. 请求底座

### 1.1 限流与重试

- **限流**：`_throttle()` 保证两次请求间隔不小于 `api.request_interval`（默认 0.1s），基于实例级时间戳，多 fetcher 实例各自独立；
- **重试**：最多 `max_retries`（默认 3）次，指数退避 `retry_delay × 2^attempt`；
- **失败语义**：网络异常、HTTP 错误、业务错误（`ErrorNo != 0`）、解析异常统一走重试；重试耗尽返回 `None`，由调用方决定跳过或中止。获取方法**不抛异常**，以 `None` / NaN 表达失败。

### 1.2 API 地址管理

API 地址不落配置文件、不硬编码（v2.0.1 起移除硬编码 IP），读取顺序：环境变量 `KLINE_API_BASE_URL` → 配置 `api.base_url`，两者皆空则抛 `EnvironmentError`。目的：敏感地址走 `.env` / CI Secret，不入库。

### 1.3 字段单位换算（实测确认）

中焯 API 原始字段单位与直觉不同，2026-06 经与东财/新浪公开基准实测确认：

| API 字段 | 原始单位 | 换算 | 目标单位 | 依据 |
|----------|---------|------|---------|------|
| Open/High/Low/ClosePrice | 万分之一元 | ÷ 1,000,000 | 元 | `PRICE_SCALE`，round 到 4 位 |
| PeriodTurnover | 万元 | ÷ 10,000 | 元 | `TURNOVER_SCALE`，round 到 2 位 |
| PeriodVolume | 股 | 不换算 | 股 | 茅台实测中焯/新浪 = 1.0000，且 成交额÷成交量≈股价 自洽 |

## 2. 市场推断与指数支持

### 2.1 代码格式

统一接受 `"600519"` / `"SH600519"` / `"sh600519"` / `"sz000001"` 等格式，请求前剥离前缀取纯数字码。

### 2.2 推断顺序（指数优先）

```
1. 显式 sh/sz/bj 前缀        → 直接按前缀市场
2. 指数白名单 INDEX_CODE_MAP  → 按指数所属市场（sh=1）
3. 399 前缀（深证系列指数）    → 深市（market=0）
4. 个股号段规则：
   600/601/603/605/688/689 → 沪；000/001/002/003/300/301 → 深；
   8/4/920 → 北；其余默认深
```

### 2.3 已知歧义（有意设计）

裸码 `"000001"` 既是上证指数（沪）也是平安银行（深）。本项目**指数优先**：白名单内裸码按指数处理。取深市个股必须显式 `"sz000001"` 或显式 `market=0`。`converter.code_to_qlib_dir` 与 `infer_market` 规则保持一致（指数白名单 → `sh000001`，个股 → `sz000001`）。

指数白名单（`INDEX_CODE_MAP`，2026-08 扩充至 26 个）：沪市 12 个（000001 上证指数、000010 上证180、000015 上证红利、000016 上证50、000300 沪深300、000688 科创50、000698 科创100、000852 中证1000、000903 中证100、000905 中证500、000906 中证800、000922 中证红利）、深市 13 个（399001 深证成指、399004 深证100、399005 中小板指、399006 创业板指、399102 创业板综、399106 深证综指、399107 深证A指、399295 创业板50、399303 国证2000、399311 国证1000、399971 中证传媒、399997 中证白酒、399998 中证煤炭）、北证50（899050，market=103）。完整对照表见 AGENTS.md「指数行情使用注意」。

## 3. 复权方案（v2.0.0 起）

### 3.1 为什么选后复权

| 方案 | 除权时对已存数据的影响 | 增量追加 |
|------|---------------------|---------|
| 前复权 (qfq) | 历史价格全部改变 | 已存数据失效，需全量重写 |
| **后复权 (hfq)** | **历史不变，仅新数据受影响** | **天然支持** |
| 不复权 | 价格断点，回测失真 | — |

### 3.2 factor 计算（fetch_day_kline_with_factor）

对同一股票发起两次请求（hfq + none），按日期对齐后：

```
factor          = hfq_close / none_close
volume（后复权） = none_volume / factor        # 与价格同口径缩放
```

还原关系：`原始价 = 后复权价 / factor`，`原始成交量 = 后复权成交量 × factor`。

### 3.3 脏数据防御（2026-08 增强）

后复权数据在数学上满足 `factor >= 1`（后复权价 ≥ 不复权价）。数据源偶发复权计算错乱（实例：600180 于 2026-08-14 出现 `low=-12.5`、`close=0`、`factor<1`）。校验规则：

1. hfq 四价（O/H/L/C）全部存在且 > 0；
2. none_close 存在且 ≠ 0；
3. 计算出的 factor ≥ 1.0。

任一不满足 → **整条记录 OHLCV+factor 全部置 NaN** 并打 warning（含原始数值便于排查）。仅置 factor=NaN 而保留坏价格会让坏值混入 bin 文件，因此选择整条作废。配合 `check_local_coverage(nan_aware=True)` 可识别 NaN 拉长的伪覆盖并触发重下。

## 4. Qlib bin 存储格式

### 4.1 文件布局

每个股票目录（如 `features/sh600519/`）下 7 个字段 × 频率各一个文件：`{field}.{freq}.bin`。

### 4.2 编码

- dtype：float32 小端序（`<f`）；
- **首元素**：该股票第一条数据对应的全局日历索引 `start_idx`；
- **其余元素**：从 `start_idx` 起按日历逐槽排列的数值；非交易日不占槽（日历本身只含交易日）、停牌/缺失/脏数据槽位为 NaN。

### 4.3 写入字段与 vwap

`["open", "high", "low", "close", "volume", "factor", "vwap"]`。vwap 不来自 API，由 `vwap = amount / volume`（volume > 0 时）在写入时临时计算；amount 字段仅作为中间量，不落盘。

## 5. 交易日历方案

### 5.1 日日历

`ensure_calendar`：取上证指数（000001）日K，逐年拉取（begindate/enddate）取并集去重排序。上证指数覆盖所有 A 股交易日，无需独立日历接口。

### 5.2 分钟日历

`generate_min_calendar` 基于日日历 × 交易时段模板生成：

- **1min：240 条/日**。中焯用「周期结束时刻」标记K线：09:31~11:30、13:01~15:00。**不含 09:30 和 13:00**（API 不返回这两个时刻，v3.0.1 修正：此前 242 条导致两个永久 NaN 槽）；
- **5min：48 条/日**，09:35~11:30、13:05~15:00（5min 数据源含 09:30/13:00 起点语义，按结束时刻取整点后边界）；
- 15/30/60min：由通用模板 `_generate_generic_min_timestamps` 推导。

关键约束：**日历必须覆盖 API 实际返回的每个时间戳**，否则 `_build_min_arrays` 找不到索引、数据被静默丢弃；反之日历多出的槽位永远是 NaN，会拉长文件造成伪覆盖。

## 6. 增量追加算法（_append_bin）

写入模式：`overwrite`（整文件重写）与 `append`（增量合并）。`_append_bin` 处理新旧数据段的五种位置关系：

| 情形 | 处理 |
|------|------|
| 新段完全在旧段内 | 丢弃（无新信息） |
| 新段在旧段之后（有间隙） | NaN 填充间隙后拼接 |
| 新段在旧段之前（有间隙） | 新段在前 + NaN 间隙 + 旧段 |
| 新旧重叠（新起点更前） | 重叠区逐槽合并 |
| 新旧重叠（新起点在旧段内） | 旧段前缀 + 重叠区合并 + 较长者的尾部 |

**NaN 保护**（v3.0.0 #6/#7 修复）：重叠区合并规则为 `np.where(isnan(new), old, new)` —— 新数据的 NaN **不覆盖**旧有效值。防止部分下载（如当日只下载了一半分钟K）把已有完整数据冲成 NaN。

**start_idx 校验**（v2.0.2 修复）：读取时校验首元素非 NaN/Inf 且幅值合理（< 1e10），异常视为损坏返回 `(None, None)` 触发重下。

## 7. 增量下载策略（download.py）

### 7.1 覆盖检查

`check_local_coverage` 返回 bin 文件覆盖的日历索引区间 `[start_idx, end_idx]`：

- 默认：`end_idx` = 文件末尾槽位；
- `nan_aware=True`：`end_idx` = 最后一个非 NaN 槽，全 NaN 返回 `(None, None)`。用于检测「日历扩展了但数据没下载」的伪覆盖。

### 7.2 日K增量

- 日期范围 > 1500 交易日时分段下载（规避 API 单次上限）；
- 每段独立判断覆盖：`local_start <= seg_start && local_end >= seg_end` 则跳过该段；
- 全段已覆盖 → `up_to_date` 跳过整只股票。

### 7.3 分钟K增量

- 翻页次数自动计算：按日期范围换算交易日数 ÷ 每页可容纳天数 +1；
- **停牌容差**（v3.0.0 #5 修复）：跳过条件为 `local_end >= end 当天最后索引 - bars_per_day`。原实现要求精确覆盖 end 当天，停牌股本地永远缺 end 当天时间戳，导致每次运行都全量重下。现容许「覆盖到 end 前一天」即视为最新。

### 7.4 状态统计

每只股票结果记入 status dict：`downloaded` / `up_to_date` / `download_failed` / `write_failed` / `no_data_in_range`，汇总成功/失败/跳过计数。

## 8. 数据正确性防线汇总

| 防线 | 位置 | 作用 |
|------|------|------|
| 单位换算实测锚定 | `_base.py` `_convert_*` | 万分之一元/万元 → 元、股 |
| 限流 + 指数退避重试 | `_base.py` `_request` | 抗瞬态故障 |
| 复权脏数据校验 | `_base.py` `fetch_day_kline_with_factor` | factor≥1、四价为正，否则整条 NaN |
| 分钟 time 字段强校验 | `converter.py` `_build_min_arrays` | 缺 time 显式跳过（v3.0.0 #3，原 00:00:00 回退会静默丢数据） |
| 追加 NaN 保护 | `converter.py` `_append_bin` | 新 NaN 不覆盖旧有效值 |
| 伪覆盖检测 | `converter.py` `check_local_coverage(nan_aware)` | NaN 拉长的覆盖不误判为有效 |
| 单元测试 | `tests/` | 上述每条防线均有 mock 测试覆盖 |
